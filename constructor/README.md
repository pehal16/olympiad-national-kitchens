# Конструктор олимпиад и тестирований

Самостоятельный модуль существующей платформы. Его база, учётные записи, файлы и процессы отделены от ресторанной олимпиады и PM01.

## Запуск Windows без интернета

Распакуйте **весь** автономный комплект в отдельную папку и откройте `Запустить.cmd`. В окне появятся адрес кабинета и адреса для участников в локальной сети. Первый владелец создаётся через форму кабинета; одноразовый код находится в `data/Первый вход.txt`. Задайте собственный пароль. Не раздавайте участникам папку данных или код настройки.

Для доступа с других компьютеров разрешите входящие TCP-соединения на выбранный порт (по умолчанию 3210) только в доверенной сети колледжа. Это действие выполняет администратор Windows. Внешний интернет для работы, шрифтов, иллюстраций и PDF не требуется. Для остановки используйте Ctrl+C в окне запуска. Папка `data` сохраняется при обновлении приложения; новую версию распаковывайте отдельно и задавайте прежнюю папку через `CONSTRUCTOR_STORAGE`.

## Работа организатора

1. Создайте проект с нуля или скопируйте один из трёх учебных образцов. Ресторанный образец сохраняет пять туров, 36 заданий и максимум 150 баллов; это копия материалов без данных студентов.
2. Настройте туры, задания, ключи и критерии. Случайный выбор из авторского набора требует одинакового максимума вопросов; каждый участник получает фиксированный вариант. Задания можно сохранять в личный банк, импортировать из CSV/XLSX и добавлять в другие проекты.
3. Проверьте отдельные задания в предпросмотре и пройдите весь маршрут кнопкой «Пробное прохождение». Пробы хранятся отдельно от настоящих проведений и не входят в награждение.
4. Опубликуйте редакцию. Дальнейшие изменения черновика не меняют выданные варианты, правила или начатые попытки.
5. Создайте проведение из опубликованной редакции. Выберите открытый вход или персональные коды, расписание в МСК, лимиты времени и попыток, порядок учёта повторов и раскрытия результатов. Сохраните созданные коды сразу: повторно открытым текстом они не выдаются.
6. Откройте вход. Участник видит отдельно локальный черновик и подтверждение сервера. После разрыва связи ответы повторяются с тем же ключом сохранения; конфликт версий требует явного выбора.
7. Проверьте ручные ответы по критериям и примите решения о переходах. Незавершённые работы не выдаются за завершённые: при необходимости исключите их из итогового зачёта, указав причину. История сохраняет ответы, проверки и решения.
8. Назначьте получателей авторских номинаций, проверьте предварительный список наград и утвердите его. Только затем запускайте выпуск. Изменение результатов или номинаций снимает утверждение и приостанавливает прежние документы.
9. Скачайте индивидуальные PDF, ZIP или общий PDF для печати. Исправление выданного экземпляра оформляется перевыпуском с причиной; предыдущая запись остаётся в реестре.

Пароль собственного кабинета меняется в настройках; прежние сеансы после смены закрываются.

Владелец приглашает педагогов ссылками сроком на 72 часа и ограничивает публикацию, проведение, проверку, награждение и предоставление доступа. Общий материал доступен только явно указанным педагогам; редактирование требует собственной копии. Результаты проведений не становятся общими вместе с материалом.

## Документы

В комплекте 12 редактируемых шаблонов: диплом, грамота, сертификат и благодарность в классическом, современном и тематическом стилях. Используются локальные кириллические PT Serif, PT Sans, Noto Serif и Noto Sans; лицензии находятся рядом с файлами шрифтов. Подписи, печати и логотипы загружает организатор.

Редактор поддерживает текст и поля, изображения, фигуры, фон, слои, блокировку, перемещение и размеры в миллиметрах, выравнивание, отмену/повтор и книжный/альбомный лист. Перед выпуском проверяйте предпросмотр с длинными ФИО и PDF: при переполнении блок уменьшается до установленного минимального кегля; если этого недостаточно, выпуск останавливается с указанием текста.

QR необязателен. Для онлайн-выпуска задайте `CONSTRUCTOR_PUBLIC_ORIGIN` с HTTPS-адресом этой установки. Локальная установка без адреса реестра не печатает недействующую ссылку. Импорт завершённых результатов регистрирует записи в принимающей установке; локальные и онлайн-реестры не синхронизируются автоматически.

## Перенос и резервные копии

В настройках доступны два пакета `.olypack`: материалы и завершённые результаты с документами. Пакет зашифрован AES-256-GCM; пароль минимум 10 символов. Он содержит версию состава, контрольные суммы, связанные изображения, шрифты и лицензии. Пароли пользователей, сессии, персональные коды и серверные секреты не переносятся.

Импорт сначала показывает состав и конфликты. Повторный импорт того же содержания для того же педагога не создаёт записи. При совпадающих идентификаторах создаётся отдельная копия со связями внутри неё; исходные записи сохраняются. Импортированные результаты открываются как закрытый архив. Активное проведение имеет один источник записи и не переключается между компьютерами.

Полная `.olybackup` содержит базу, медиа и выданные PDF. Можно включить ежедневные зашифрованные копии с хранением последних семи. Копии на том же диске следует дополнительно сохранять на отдельный носитель. Пароль расписания хранится в приватной папке данных: ограничьте доступ к ней средствами ОС.

Восстановление разрешено только в новую пустую папку. В Windows вызовите `Восстановить.cmd "полный путь к копии.olybackup" "полный путь к новой папке"`; пароль вводится отдельно. В исходном проекте: `CONSTRUCTOR_BACKUP_PASSWORD=... node scripts/restore.mjs <копия> <новая папка>`. Проверяются контрольные суммы и целостность SQLite; старые административные сессии сбрасываются.

## Разработка и приёмка

Node.js 24, затем `npm ci`, `npm run build`, `npm run dev`. Интерфейс доступен на `http://127.0.0.1:3210/constructor/`; Vite для разработки — `npm run dev:ui`. Вложенный адрес задаётся в `vite.config.mjs`. API: `/api/constructor/v1/`. В продакшене запускается `node dist/server.cjs`.

Переменные: `CONSTRUCTOR_STORAGE`, `CONSTRUCTOR_HOST`, `CONSTRUCTOR_PORT`, `CONSTRUCTOR_ASSET_ROOT`, `CONSTRUCTOR_CHROMIUM`, `CONSTRUCTOR_PUBLIC_ORIGIN`. Chromium берётся из явного пути; на Windows автоматически используется установленный Chrome/Edge. Автономный комплект включает собственный браузер и Node. Сборка: `npm run package:windows` после build; выходную новую папку задаёт `CONSTRUCTOR_RELEASE_DIR`, ZIP — `CONSTRUCTOR_ZIP=1`.

- `npm test` — оценивание, права и CSRF, версии, таймеры, перенос, резервные копии и PDF.
- `npm run verify` — настоящий браузерный маршрут с мобильным viewport, сохранением после перезагрузки, потерей связи, ручной проверкой, утверждением и PDF. Свидетельства задаются `CONSTRUCTOR_EVIDENCE`.
- `npm run load` — 100 одновременных участников, 2 000 ответов и 400 повторных отправок одновременно с 12 PDF; проверка потерь, дублей и p95 ≤ 2 с. Собственная временная база удаляется после проверки. Отчёт — `CONSTRUCTOR_REPORT`.
- Для проверки выделенного сервиса можно задать `CONSTRUCTOR_ACCEPTANCE_BASE`, `CONSTRUCTOR_ACCEPTANCE_LOGIN`, `CONSTRUCTOR_ACCEPTANCE_PASSWORD`. Эти проверки создают явно помеченные синтетические проекты и результаты; не запускайте их в чужом кабинете.

Браузерная автоматизация с мобильным viewport не заменяет проверку реального телефона и самостоятельную приёмку педагогом. Учебные образцы требуют предметной проверки перед настоящим проведением. Текущие доказательства выпуска и ограничения перечисляются в `docs/constructor-release.md` основного проекта.

Архитектура Vite: https://vite.dev/guide/backend-integration.html. Печать Chromium с фиксированным CSS-размером: https://playwright.dev/docs/api/class-page#page-pdf.
