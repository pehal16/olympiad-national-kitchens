## Оценка, сохранение и совместимость

- 3 станции, выбор 3 / 2 / 2 блюд; 7 блюд, 56 компонентных позиций.
- Ровно 4 разных компонента из 8. Подходящий — 4 балла, посторонний — 0, штрафов нет. До 16 / 48 баллов; 15 минут с момента входа в тур, включая правила. Общий маршрут 36 заданий / 150 баллов / 45 минут.
- Все 70 сочетаний и 24 порядка каждого сочетания для каждого блюда: **11 760 оценок**. Проверены 0, 4, 8, 12 и 16 баллов; порядок ничего не меняет.
- Отклоняются чужие ID, повторения, 3 / 5 компонентов, нестроковые ID и дополнительные ключи payload. Без server-fixed выбора ответ не принимается.
- Выбор через CAS ревизии `stationSelections`: тот же запрос идемпотентен, другой выбор отклоняется. Выданный вариант и прежние ответы не переписываются. Проверены unit, file, SQLite/D1 HTTP и два одновременно действующих браузерных клиента.
- Токен попытки обязателен; чужая станция и просроченный ответ отклоняются. После дедлайна несохранённая сборка не получает баллы. Дедлайн проверен на HTTP уровне; отдельное ожидание 15 минут в браузере не выполнялось.
- При потере успешного acknowledgement UI запрашивает `answerReceipt` конкретного выданного T5 question ID. Факт сохранения не выводится из локального выбора или общего счётчика. Повтор не создаёт второй ответ.
- До закрепления API выдаёт только превью текущей станции, после — восемь компонентов выбранного блюда. Нет исходных семантических ID, ключей и следующих станций. Квитанция содержит только question ID и `saved`, не выбранные компоненты.
- Исторический `data/banks/tour5.js` и банки T1–4 не изменены. Старый blueprint 9 / 45 заданий / 12 вопросов T5 проверен на сохранённой HTTP-попытке: прежний вопрос выдаётся и оценивается, вариант побайтно не меняется, максимум старого T5 остаётся 48.

## Реальный Chrome: desktop и mobile

Установленный Chrome через кешированный Playwright; новых браузерных зависимостей в проекте нет. Адрес `http://127.0.0.1:3187`, отдельная временная SQLite/D1-совместимая база, только синтетические участники. Production-попытки и результаты не использовались и не изменялись.

[Полный визуальный отчёт](assets/t5/visual-pizza-burger-shawarma-greek-caesar-khachapuri-roll.json):

- Основной агент лично просмотрел **7 сцен, 56 карточек, 56 отдельно показанных слоёв**, включая ложные, и **7 превью**. У каждого компонента есть видимый слой; ошибок загрузки нет.
- Desktop 1505×1045: сцена/состав ~70/30, карточки 4×2, равные размеры, два настоящих таймера, без признаков правильности и игровых эффектов.
- Все 7 блюд при ширинах **320 / 360 / 375 / 390 / 430**: 35 проверок без горизонтального overflow, карточки 2×4, управление не меньше 44 px. Телефон: сцена → счётчик → карточки → компактные выбранные chips → подтверждение.
- Click/tap меняет один payload; четвёртый разрешён, пятый блокируется. Удаление, очистка, поворот/сброс работают. Touch-панель сохраняет вертикальную прокрутку; на телефоне поворот кнопками.
- Keyboard Enter / Space / Tab, видимый focus; native mouse drag на сцену добавляет компонент, drop вне сцены ничего не меняет. Неполный draft после reload восстановлен, submit выключен.

[Полный маршрут и отказоустойчивость](assets/t5/flows.json):

1. Desktop **T4 → правила T5 → подтверждение/отмена → reload → Маргарита / греческий / хачапури → результат**. T5=48, всего 150, 36 ответов в SQLite; прежняя кнопка сертификата доступна. При завершении WebGL освобождён.
2. Mobile **390×844**, touch-эмуляция: **чизбургер / Цезарь / Филадельфия → результат**. Те же 48 / 150; три станции через настоящие taps.
3. Досрочное завершение неполной сборки: предупреждение, T5=0, прежние 102 балла сохранены.
4. Потеря сети после реальной записи ответа: восстановление по квитанции, один ответ, переход к следующей станции.

[Дополнительные браузерные проверки](assets/t5/extra.json):

- Offline-подтверждение оставляет блюдо незакреплённым, показывает ошибку; сборка оптимистически не открывается. После восстановления связи можно продолжить.
- Два клиента одновременно подтверждают разные блюда: оба переходят к одному действительно зафиксированному выбору.
- Service worker контролирует страницу после reload; T5 JS/CSS в актуальном кеше `national-kitchens-olympiad-v1-7-0-t5kitchen-1`; API-ответов в кеше нет.

В итоговых визуальном и дополнительных отчётах нет page errors; в визуальном также нет console errors и HTTP-ошибок. Сетевой отказ в специально нарушенном сценарии — ожидаемая проверка, не обещание полного прохождения без сети.

## Fallback / reduced motion

- WebGL искусственно недоступен: рабочая 2D-сцена с теми же фото; 4 компонента и основа «Маргариты» видны; ответ принят по тому же контракту.
- Настоящий `WEBGL_lose_context` перевёл сцену в 2D без потери выбранного компонента.
- `prefers-reduced-motion: reduce`: анимация списка `none`, сцена без анимации. Обычно короткие переходы около 180 ms, без бесконечного игрового цикла.
- После визуальной проверки уменьшен предел 2D-основы до 320 px desktop / 235 px mobile: нижний край не обрезается. Итоговый [fallback](assets/t5/fallback-reduced-motion.png) лично просмотрен после исправления.
- Фотографические плоскости в объёмной сцене — **не полноценные объёмные модели продуктов** и не физический симулятор приготовления. «Филадельфия» — разрешённая условная плоская раскладка на доске.

## Концепты и fidelity ledger

До реализации просмотрены 4 отдельных нативных концепта: desktop-сборка, выбор/подтверждение, intro, mobile. Полные промпты/пути: [реестр](olympiad-t5-asset-provenance.json), `concepts`. Белый #ffffff, зелёный #15826f, тёмный #202b2a, Georgia / Arial, радиус 12 px. Существующий exam guard сохранён; декоративные панели скрываются только в новом T5.

| Критерий | Экспертная оценка / 5 | Основание |
|---|---|---|
| Компоновка и иерархия | 4,5 | Desktop 70/30 и 4×2; mobile 2×4; длинный экран требует прокрутки |
| Цвет и типографика | 5 | Белая/зелёная система, Georgia/Arial |
| Фото и слои | 4 | Все 56 распознаваемы; фото-плоскости условны, перекрытие в многослойном блюде возможно |
| Состояния концептов | 4,5 | Все 4 реализованы нативно; настоящие таймеры/статусы, не растровый UI |
| Управление и честность | 5 | 44 px+, доступные кнопки; draft не объявляется ответом, запись подтверждает сервер |

Это оценка основного агента, не измеренный студенческий usability score. Намеренные отличия: прозрачные cutout вместо мисок; точные названия «Томатный соус»/«Шампиньоны»; случайный порядок вместо правильных сверху; крупнее мобильные зоны нажатия; компактные chips; честный серверный статус. Концепты не отправляются участнику вместо HTML.

## Ограничения и выпуск

- Технически готов для **новых попыток после согласованной публикации**. Эта задача не даёт нового разрешения push/deploy; production остаётся прежним.
- Не проверены физические телефоны, Safari/Firefox, доступ через разных российских провайдеров и нагрузка 50–60 участников. Touch-эмуляция не заменяет такие проверки.
- Равную трудность семи блюд нельзя доказать количеством карточек. Нужны преподавательская приёмка и студенческий пилот с анализом выбора/баллов.
- Проверяется состав версии, не физическая последовательность, тепловая обработка и безопасность сырой рыбы.
- Удаление ключей из API не скрывает их от читателя публичного GitHub. До официальной олимпиады нужно решить доступ к исходникам/документам организатора; видимость не менялась.
- Production после нового deploy не проверялся: публикации не было. PM01 smoke — техническая регрессия, не закрытие прежних замечаний `docs/learning-methodical-audit.md`.
