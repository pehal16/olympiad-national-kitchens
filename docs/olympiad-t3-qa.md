## Реальный браузер, desktop и mobile

Playwright с установленным Google Chrome, headless, без установки зависимости
в проект. Desktop 1440×1000; mobile 390×844, touch, `reducedMotion: reduce`.
Использован локальный API и изолированное временное file-хранилище только с
синтетическими участниками. Настоящие личные данные/production не читались и
не изменялись. Для перехода к T3 первые два тура пройдены API-запросами с ключами
только синтетических вариантов; сам T3 целиком пройден вводом и кнопками UI.

На каждом устройстве введены все десять ответов:
`сырники`, `дранеки`, `омлет`, `samsa`, `хумсу`, `яблочный штруедль`,
`чизкейк`, `чипсы`, `гуакомоле`, `фалафель`.
Сохранённые сервером оценки: `[3, 3, 0, 3, 3, 3, 3, 0, 3, 3]`, ровно 24/30,
штрафы нулевые. Ровно 10 POST сохранения на прохождение, без JS/console ошибок.
Оценки отдельных ответов не показывались участнику во время прохождения.

Проверено:

- Вводный экран 10/30/8; кнопка «Начать тур»; чтение входит в серверный таймер.
- Один символ не включает подтверждение; два включают; «Очистить» очищает ввод.
- Черновик `творожники` восстановлен после reload; вводный экран не повторяется.
- Tab: поле → подтверждение → очистка; Enter даёт одну отправку; IME composition
  Enter не отправляет незавершённый ввод. Существующий fullscreen guard сохраняется.
- Три подсказки и локальный загруженный WebP на каждом вопросе.
- Ширины 320/360/375/390/430 на каждом из десяти вопросов без горизонтального
  переполнения, цели ≥44 px. Дополнительно просмотрены длинные досье 4 и 6.
- При уменьшении viewport до 390×400 поле и подтверждение доступны. Это симуляция
  уменьшения viewport, **не** проверка физической экранной клавиатуры Android/iOS.
- Массив вместо строки, 121 символ и поддельный `finalScore` получают HTTP 422,
  не переводят на следующий вопрос. Current API не раскрывает ключ проверки.
- После T3 открывается существующий T4; общая кнопка возвращается в action deck.

## Ошибки и крайние состояния

- Исправлена нестабильность hover: у общей кнопки на T3 отключён сдвиг, из-за
  которого реальная проверка click могла зациклиться. Остальные туры не затронуты.
- Исправлена блокировка кнопки повторной отправки, перенесённой внутрь досье.
  При очереди блокируются поле и очистка, а не вся содержащая retry кнопка.
- Реальный сетевой тест: три POST оборваны; вопрос не продвинулся, запись отсутствует.
  После восстановления сети кнопка retry доступна, ровно один успешный POST,
  сервер хранит ответ и 3 балла один раз; следующий ввод снова доступен.
- HTTP 404 иллюстрации: виден нейтральный fallback, остаются все три подсказки,
  ответ успешно сохраняется. Для воспроизводимого сбоя картинки SW блокировался
  только в тестовом browser context, не в приложении.
- Запрет `getItem/setItem` для ключей T3: интерфейс и отправка работают в памяти,
  без необоснованного обещания долговечного черновика. Сохранение после закрытия
  браузера при запрещённом storage не гарантируется.
- Дополнительный аудит обнаружил ложные fuzzy совпадения `сырки`, `пряники`,
  `салса`: добавлены явные запреты. Повторный настоящий UI/API тест первых четырёх
  досье с вводом `сырки`, `пряники`, `шакшука`, `салса` сохранил `[0, 0, 3, 0]`.

на телефоне. Часть внешних краёв предметов на исходных фото близка к границе,
ключевые ингредиенты читаются; ограничения фалафеля и размера тёрки раскрыты в реестре.

## Оставшиеся ограничения

Нужен пилот русскоязычных студентов СПО, особенно по шакшуке, самсе, хумусу,
начос, гуакамоле, фалафелю. Fuzzy — ограниченная проверка написания, не доказательство
смысловой равнозначности всех названий мира. Физические Android/iOS, реальные
мобильные клавиатуры и нагрузка на production в этом задании не проверялись.
T4 не перерабатывался; миграция ранее выданных попыток не выполнялась.
