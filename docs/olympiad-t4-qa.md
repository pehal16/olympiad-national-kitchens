## Функциональные границы

- На первом заказе правила читаются уже внутри серверных 10 минут. Повторное
  открытие правил, увеличение фото, Escape и reload не меняют startedAt.
- Все четыре позиции равны по карточкам/загрузке. Предзагрузка фото будущих
  заказов не обнаружена: список реальных запросов сверялся с уже выданными.
- Нажатие/касание заменяет ровно один выбор немедленно. Очистка возвращает
  фокус и пустой поднос; ни выбор, ни замена, ни очистка не отправляют POST.
- Реальный mouse DnD проходит все 8 заказов. Drop вне подноса, Escape и
  touch pointercancel сохраняют предыдущий выбор, не создают ответ.
  Native mouse pointercancel на старте HTML DnD не считается отменой:
  браузер передаёт управление drag-событиям; отмена определяется dragend/Escape.
- Tab, Enter, Home и стрелки работают; `radio`/`aria-checked` отражают единое
  состояние. Модальные окна возвращают фокус на кнопку и не меняют выбор.
- Одна настоящая двойная мышиная активация при задержке HTTP даёт 1 POST.
  Дубликат ответа с другим выбранным блюдом не переписывает первую запись.
  Два конкурентных одинаковых запроса проходят с одним шагом/одной revision.
- Без токена / с чужим токеном — 401; чужая опция, опция следующего вопроса,
  массив вместо строки и лишние ключи — 422. Неизвестный question ID даёт
  существующий контракт soft-sync 200, **без записи и без receipt.saved**;
  это не принятие поддельного ответа. Полный снимок storage не меняется.
- Правильные/ошибочные/смешанные/пустые ответы проверены тестами: 32/0/16
  за полный T4, 4/0 за заказ, штраф всегда 0. В UI нет оценки правильности.
- Неудача трёх сетевых попыток оставляет точный выбор заблокированным,
  retry-кнопка доступна и не находится внутри inert. Reload после восстановления
  связи сохраняет ровно один ответ, следующий поднос пустой.
- Запрет localStorage приводит к memory fallback с честной оговоркой про
  потерю черновика после reload. Обычный reload восстанавливает выбранное блюдо
  только для этой попытки/версии/вопроса.
- 404 всех четырёх фото даёт «Фото недоступно», полный заголовок и подпись;
  заказ всё ещё можно выполнить, подтвердить и получить серверную запись.
- Досрочное завершение отправляет выбранный черновик через общую очередь
  ровно один раз. Итоговый статус в синтетическом прогоне — `reviewed`.
- Истечение серверного T4 deadline во время выбора/запроса переводит в T5
  без позднего ответа и балла. Узкий `answerReceipt` сообщает только qid и
  факт записи; клиент показывает «Заказ не записан», не ложное сохранение.
- Статус прежнего ответа не называется сохранением текущего подноса:
  при выборе «Заказ ещё не отправлен», при sync — «Предыдущие ответы сохранены».

Основные receipts: `browser-results.json`, `edge-results.json`, `api-results.json`.
Физический touch отмены не имитировался как native DnD: мобильный путь — tap;
pointercancel проверен синтетическим событием. Нельзя называть это тестом Safari.

## Визуальная проверка, пять критериев

Цель — текстовый бриф пользователя и существующая визуальная система T2/T3.
UI-концепт через ImageGen **не генерировался** по прямому запрету пользователя.
Главный агент лично открыл каждый оригинал, каждый WebP и все восемь desktop
и восемь mobile экранов (не одну контактную таблицу).

| Критерий | Сверка с брифом / результат |
|---|---|
| Иерархия и спокойный экран | Два реальных таймера, один прогресс, один заголовок, пожелание гостя, меню, поднос. Лишний cockpit/повторные метки убраны только для T4. PASS |
| Равенство четырёх вариантов | Одинаковый размер/фон/доступ к zoom, без флагов/оценок. Первоначальный чебурек отклонён и переделан по замечанию пользователя; согласованы подписи говядины/наггетсов. PASS с возможностью пользовательской эстетической правки |
| Состояние и подтверждение | Зелёная рамка означает только «выбрано вами», поднос показывает одно блюдо. Анимация не управляет моделью; неподтверждённый выбор явно назван. PASS |
| Малые экраны и длинный текст | 320/360/375/390/430 px: 0 горизонтального overflow, все доступные кнопки ≥44 px, подписи без ellipsis. При text-size 200% меню переходит в одну колонку; страницу нужно вертикально прокручивать. PASS |
| Доступность и соседние туры | Видимый клавиатурный фокус, modal Escape/focus return, reduced-motion, естественный переход T3→T4→T5, нет sticky-overlay над блюдами. PASS в Chrome, физические устройства не проверены |

Нормальные карточки используют contain без обрезки еды. PNG→WebP не подменяет
саму генерацию. Изображения показывают реальную структуру конкретной версии,
но состав/температуру/влажность нельзя доказывать по одному изображению —
поэтому существенные различия дополнительно названы в подписи.

Закрытые матрицы/ключи не входят в public JS/JSON и asset metadata; серверный
Worker bundle содержит ключи по назначению. `answerReceipt` не раскрывает
баллы, выбранную/правильную опцию, объяснения и будущие вопросы. Скрипты
нового тура добавлены в standalone-shell allowlist; реальный Timeweb не трогали.

Репозиторий публичный, поэтому секретность исходного серверного банка не
гарантируется после будущего push. Видимость не меняли. До настоящего запуска
нужны решение организатора по хранению ключей, преподавательская приёмка,
студенческий пилот, сетевой тест из РФ и физические браузеры/устройства.
Перечисленные технические PASS не являются заменой этих проверок.
